# 16. Testing

## 16.1 Test Pyramid (per service)

JUnit 5 + Mockito for pure domain rules; Testcontainers PostgreSQL integration for RLS, constraints, row locks, inbox/replay/publication atomicity. Jest for Angular unit/components; Playwright for source use cases. These are planned application tests, not a claim of execution in this documentation stage.

## 16.2 Unit Test Conventions

Name methodName_scenario_expectedResult. Inject Clock, fixed random/id generators where appropriate, and parameterize Money/date rules. Test receipt proportional discount/day30; code latest/expiry/5th failure; payout refusal versus unknown response; capped points including 12.80 EUR cents and later -80 take-back.

## 16.3 Integration Test Conventions

Never mock repositories. Use real PostgreSQL with app role/RLS and concurrent barriers: submit/approve/cancel on one purchase; two correction/refund writers; callback versus deadline; code issuance versus confirmation. Add API-14 first-success/first-error replay tests with no new hash-conflict contract error, and late-rejoin replay against a simultaneous refund using purchase-before-member lock order. Kill process after aggregate commit, after provider acknowledgement and before acknowledgement persistence. Re-run original identity and assert one business effect, durable work and restored tenant/MDC.

## 16.4 Contract Tests

Verify acyclic Spring Modulith dependencies, exposed API packages, three payouts-owned DTOs and customer-accounts-owned API-14. Serialize/deserialize all ten source catalog event records across current/previous application versions and stable listener identities. API-12/13 read transactions and API-14 first error replay require adapter tests. External stubs exercise source-defined outcomes; their shapes/signatures cannot be certified until §9 external TODOs are settled.

## 16.5 Frontend Tests (if applicable)

Jest covers guard behavior, blur validation, formatters, screen-only telemetry and loading/empty/error states. Playwright covers exact source AC/E/A paths. Browser accessibility automation is supplemented with keyboard/screen-reader observation; no automated score alone proves WCAG AA.

## 16.6 Test Data Strategy

Use BRD chunk 16 prerequisites with synthetic customers, branches/covers, members, receipts and provider stubs. No production PII. UTC Clock is settable in Dev/SIT/UAT only; Prod binds a system UTC clock with no public override. Branch zones and tenant correction zone are distinct; fixture tenant zone is America/Chicago, owner LOYALTY. Stub provider IDs stay synthetic until contracts arrive.

## 16.7 CI Gates

Module boundary verification; unit/component/integration suites; real DB invariant/tenant tests; OpenAPI compatibility; publication DTO compatibility; e2e tag/route coverage. Promotion still needs both source BAT sign-offs and the go-live balance import. No stage-added acceptance switch or closed member-route business gate. Tool selection and security release policy remain upstream TODOs.
