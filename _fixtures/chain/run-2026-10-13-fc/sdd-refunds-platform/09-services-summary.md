# 13. Services Decomposition (Summary)

All four rows are modules of the one deployable `refunds-platform-app` (ADR-01); each `13x` chunk is a module spec on the service template.

| Service | Type | Overview | Responsibility | Use cases (BRD) | Owns DB | Input | Output | Business Logic (Summary) | Integrations | Characteristics | Status |
|---------|------|----------|----------------|-----------------|---------|-------|--------|--------------------------|--------------|--------------------|--------|
| refund-request | module | Refund requests from submission to Paid, Rejected, or Cancelled | Owns the refund request, its items, its status, and its decision record; serves the branch refund report | [REFUNDS/UC-01](../brd-refunds-portal/06a-use-cases-customer.md#uc-01-request-a-refund), [REFUNDS/UC-02](../brd-refunds-portal/06a-use-cases-customer.md#uc-02-track-refund-status), [REFUNDS/UC-03](../brd-refunds-portal/06a-use-cases-customer.md#uc-03-cancel-a-refund-request), [REFUNDS/UC-04](../brd-refunds-portal/06b-use-cases-branch-manager.md#uc-04-approve--reject-refund) | schema `refund_request` | REST from the web app; `PayoutSucceeded`, `PayoutReturned`, `PayoutCancelled`, `CardPaymentDisputeOpened`, `CardPaymentDisputeClosed` | REST responses; `RefundRequestSubmitted`, `RefundRequestApproved`, `RefundRequestRejected`, `RefundRequestCancelled`, `RefundRequestPaid`, `RefundRequestPayoutReturned`; `CustomerContactPort` (API-06) | Eligibility check against the receipt and the started branches, refund lifecycle state machine (including a payout sent back and a disputed payment refunded by the bank), own-requests and own-branch scoping, immutable decision record, open card disputes shown at decision time | Point-of-Sale Records receipt lookup (API-04) | Customer-facing and branch-manager-facing; the only writer of refund status | Active |
| payout | module | Payouts to the customer's original card | Owns payouts and payout attempts; the only module that talks to CardPay Ltd | None - realises the payout steps of [REFUNDS/UC-04](../brd-refunds-portal/06b-use-cases-branch-manager.md#uc-04-approve--reject-refund) owned by refund-request | schema `payout` | REST from the operator screens (payout resolutions); `RefundRequestApproved`; CardPay payout results (in the API-01 response or, if CardPay calls back, API-02); CardPay card dispute notices (API-09, if CardPay reports them); `Schedule: payout-retry` | REST responses; `PayoutSucceeded`, `PayoutReturned`, `PayoutCancelled`, `CardPaymentDisputeOpened`, `CardPaymentDisputeClosed`, `PayoutAttemptFailed`, `PayoutStillFailing` | One payout per approved refund request, idempotent attempts in rounds, retry with backoff, one-day still-failing alert, hold while a card dispute is open, a new round when a paid payout is sent back, payout resolutions by hand with a second operator's confirmation | CardPay Ltd (API-01, API-02, API-07, API-09) | Money movement; operator endpoints only | Active |
| customer-notification | module | Email and SMS messages about refunds | Owns message records and the MsgHub adapter; decides which message each event gets | None - sends the customer messages of [REFUNDS 03 § Customer messages](../brd-refunds-portal/03-definitions-and-domain-concepts.md#customer-messages) and the branch-manager alert of [REFUNDS/UC-04](../brd-refunds-portal/06b-use-cases-branch-manager.md#uc-04-approve--reject-refund) E1 | schema `customer_notification` | `RefundRequestSubmitted`, `RefundRequestApproved`, `RefundRequestRejected`, `RefundRequestCancelled`, `RefundRequestPaid`, `RefundRequestPayoutReturned`, `PayoutAttemptFailed`, `PayoutStillFailing` | Messages through MsgHub (API-03) | Message selection per status change, contact lookup through API-06, branch-manager lookup through API-08, queued sending that never blocks a refund | MsgHub (API-03); platform IAM branch-manager lookup (API-08, INT-04) | Asynchronous only; no user-facing API | Active |
| loyalty-points | module | Members' points ledger | Owns points accounts, points movements, received purchases, and processed refunds | [LOYALTY/UC-01](../brd-loyalty-points/06a-use-cases-member.md#uc-01-view-points-balance), [LOYALTY/UC-02](../brd-loyalty-points/06a-use-cases-member.md#uc-02-view-points-history) | schema `loyalty_points` | REST from the web app; member purchases from POS Records (API-05); the refund outcomes `RefundRequestPaid`, `RefundRequestRejected`, `RefundRequestCancelled`, `RefundRequestPayoutReturned` | REST responses | Earning per LOYALTY 03, idempotent take-back capped per purchase from the refund-reporting start date, other refund outcomes recorded, balance as the sum of movements | Point-of-Sale Records member purchases (API-05) | Member-facing; ledger accuracy (LOYALTY/NFR-01) | Active |
