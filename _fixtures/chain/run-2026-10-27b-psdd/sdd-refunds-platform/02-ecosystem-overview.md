**Ecosystem-level rules:**

- **Event-driven by default (EDA):** in this modular monolith, module-to-module state changes use durable in-process domain events (§14.10) and `Internal (in-process)` port calls (§15); no integration event leaves the process in this release, so the platform runs no broker (§14.2). Durable provider writes that must follow a state change (a payout, a customer message) use a transactional outbox - no dual-writes. Synchronous reads (a receipt lookup, a dispute lookup, a contact lookup) and in-process events have separate guarantees.
- **DDD bounded contexts:** one module owns one bounded context, its data, and one team of decisions: one schema per module in the one PostgreSQL database, with no cross-module joins and no cross-schema reads. The §13 decomposition follows domain boundaries, not technical tiers.
- **Hexagonal architecture (ports & adapters) per module:** the domain core is isolated from transport and infrastructure; inbound and outbound adapters (REST, persistence, provider clients, event listeners) plug into ports, and modules call each other only through ports. CardPay Ltd, MsgHub, and Point-of-Sale Records sit behind anti-corruption adapters.
- **Time:** every timestamp is UTC, stored as `timestamptz`, exchanged as ISO-8601 with a `Z` offset; branch-local display uses the branch's time zone.
- **IDs:** UUIDv7 primary keys generated in the application by an in-house generator; business numbers (the reference number of a refund request) are separate columns.
- **Money:** amounts are `numeric(19,4)` with an ISO-4217 currency code; every amount on a screen shows its currency ([REFUNDS 11 § UI/UX Expectations](../brd-refunds-portal/11-summary-and-uiux.md#uiux-expectations)). **[NEEDS CLARIFICATION: Which currency or currencies do refunds and payouts use? Owner: Refunds and Loyalty Product Owner.]**
- **Module-to-module authorization:** each module port checks a permission token from §16 held by the calling module's identity ([§15.1](./11-api-contracts.md#151-contract-conventions-platform-defaults)).
- **Secrets:** no secret in code, images, or configuration files; the deployable reads them from the secrets manager at start-up; provider credentials per environment.
- **Personal data in logs and events:** customer contact details never enter the publication log or a log line; events carry IDs, and the notification module reads contact details through its port ([API-03](./11-api-contracts.md#api-03-customer-contact-lookup-notification---refund-request)).
